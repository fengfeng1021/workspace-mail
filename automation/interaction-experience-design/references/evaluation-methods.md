# 評估方法（完整版）

> **使用時機**：設計完成要驗證（啟發式評估／任務分析／可用性測試／A-B／心智模型）時；決策樹「驗證」分支。

設計完成不是憑感覺——用方法驗證。依成本從低到高排列，時間有限時從上面做下來。

## 1. 啟發式評估（Heuristic Evaluation）

**成本**：低（一人一下午）。**產出**：問題清單＋嚴重度。

**步驟**：
1. 拿 Nielsen 10 啟發式（references/nielsen-heuristics.md）當檢查表
2. 每個關鍵畫面逐條檢查
3. 記錄：違反哪條、哪個畫面、嚴重度分級
   - 0 不影響 / 1 小問題 / 2 大問題 / 3 阻斷 / 4 災難
4. 全部列完再一次修（不要邊看邊改）
5. 修完複查一遍

**技巧**：以「真實使用者任務」走一遍（不是看畫面漂不漂亮）；每個畫面至少看 2 次（一次當使用者、一次當檢查員）。

## 2. 任務分析（Task Analysis）

**成本**：低。**產出**：關鍵流程的步驟數與卡點。

**步驟**：
1. 列出 3-5 個關鍵任務（使用者最常做的、最重要的）
2. 從使用者視角一步步走：每步記「點擊、輸入、等待、理解」
3. 計算：完成任務要幾步？有沒有多餘步驟？
4. 找卡點：哪一步使用者會猶豫？（選項太多、標籤看不懂、找不到東西）
5. 優化目標：關鍵任務 ≤3 步到達、無卡點

**判斷標準**：
- 主要功能到達 ≤2 次點擊（從首頁）
- 每個畫面主動作明確（使用者不用想「下一步點哪」）

## 3. 可用性測試（Usability Testing，最有效）

**成本**：中（需要真實使用者）。**產出**：使用者實際卡在哪的證據。

**步驟**：
1. 找 5 位目標使用者（5 人就能發現 80% 問題）
2. 設計任務腳本（真實任務，不是「試試看」）
3. 觀察（可錄影）：不要提示、不要引導
4. 記錄：完成時間、錯誤次數、卡點位置、猶豫
5. 分析：共同卡點 = 必須修；個別卡點 = 次要
6. 修完再測一輪（確認修對）

**關鍵**：測「使用者在真實任務中卡不卡」，不是「喜不喜歡」。

## 4. A/B 測試（A/B Testing）

**成本**：中高（需要流量）。**產出**：哪個版本數據更好。

**步驟**：
1. 定義單一指標（轉換率、完成率、點擊率——一次只測一個變因）
2. 只改一個變數（按鈕大小？文案？位置？）
3. 分流 50/50，跑足夠樣本（統計顯著）
4. 用數據決定，不用意見

**適用**：不確定兩種設計哪個好時；不適用於「整個介面重設計」（變因太多）。

## 5. 心智模型測試（Mental Model Testing）

**成本**：低中。**產出**：使用者認為功能在哪。

**步驟**：
1. 列出功能名稱
2. 問目標使用者：「你會在哪裡找到 XX？」（或讓它直接找）
3. 記錄找到率與找的路徑
4. 找不到的 = 命名或位置不符合心智模型 → 調整
5. 也可以做卡片分類法（references/information-architecture.md）

## 方法選擇

| 情境 | 方法 |
|---|---|
| 設計中快速自查 | 啟發式評估（每輪設計都做） |
| 上線前驗證 | 任務分析 ＋ 啟發式評估 |
| 有真實使用者可找 | 可用性測試（5 人） |
| 有流量、比兩個方案 | A/B 測試 |
| 導覽與命名不確定 | 心智模型測試／卡片分類法 |

## 修復優先級

1. 阻斷任務的（無法完成、資料遺失）→ 立即
2. 高頻路徑上的卡點（每天做的任務）→ 當輪
3. 邊緣問題 → 排隊
4. 純偏好 → 記錄不做

**原則**：先修「任務完成率」，再修「效率」，最後修「滿意度」。
