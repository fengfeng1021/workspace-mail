# 設計評分閘門（Scored Gate）

設計完成後**必須**評分：滿分 100，扣到 <80 分不准交付，修完重評。評分是強制步驟（參考 StyleSeed 的 render→score→revise 機制）。

## 評分流程（工具＋人工合流）

```
1. 有 HTML 成品 → 先跑 python scripts/audit.py <檔案>（機械檢查自動扣分，輸出分數 A）
2. 人工評分 → 照下方扣分表檢查設計層面（輸出分數 B）
3. 最終分數 = min(A, B)  （取低者：任何一關不合格都不交付）
4. <80 或含任何阻斷級問題 → 列出修正清單 → 一次批次修 → 重評
5. 桌面應用（egui 等）無 HTML → 直接用人工評分（references/desktop-apps.md 有桌面加扣項）
```

## 評分方法

從 100 分開始，逐項扣分。**每發現一項就扣，誠實扣，不要心軟。**

## 扣分表

### A. 阻斷級問題（每項 -20，發現任何一項直接重修）
- [ ] 使用者無法完成主任務（流程斷掉、按鈕沒反應）
- [ ] 資料可能遺失（錯誤後清空輸入、無確認刪除）
- [ ] 完全沒有返回途徑（深層頁回不去）

### B. 嚴重問題（每項 -10）
- [ ] 主動作不明確（兩個同尺寸主按鈕、主次不分）
- [ ] 導覽無組織（功能平鋪無分組、同層 >7 項）
- [ ] 系統狀態不可見（無 loading、無完成提示、不知身在何處）
- [ ] 破壞慣例（返回不在固定位置、搜尋放奇怪地方）
- [ ] 對比度 <4.5:1（文字）或 <3:1（圖示）
- [ ] 操作無回饋或錯誤訊息無解法
- [ ] 讓使用者記憶 >4 個臨時資訊

### C. 一般問題（每項 -5）
- [ ] 次要動作比主動作顯眼
- [ ] 一屏資訊過多無視覺分組（Gestalt 未應用）
- [ ] 錯誤訊息只在頁頂、不在欄位旁
- [ ] 目標 <24px 且無間距
- [ ] 只靠 hover 顯示動作
- [ ] 命名不是使用者語言（術語、內部簡稱）
- [ ] 深層頁無標題／麵包屑
- [ ] 進階功能沒有收合（全部攤開）

### D. 加分項（每項 +5，最多 +10）
- [ ] 破壞性操作有雙重確認（輸入文字確認）
- [ ] 誤操作可復原（送出可撤回、刪除進垃圾桶）
- [ ] 空狀態有引導說明
- [ ] 尊重 prefers-reduced-motion

## 評分結果判定

| 分數 | 判定 | 動作 |
|---|---|---|
| ≥90 | 優秀 | 可交付 |
| 80-89 | 良好 | 可交付（記錄小瑕疵） |
| **<80** | **不合格** | **不准交付**：列出所有扣分項 → 一次批次修復 → 重評 |
| 有 A 類 | 無論分數 | 直接重修，不交付 |

## 評分範例

**範例 A：登入頁**
- 扣：雙主按鈕（-10）、錯誤清空輸入（-10）、對比 3.8:1（-10）、無 loading（-5）→ **65 分，不合格**
- 修：主按鈕放大＋忘記密碼降級、錯誤保留 email、對比調到 4.6:1、加 loading → 重評 95 分 ✅

**範例 B：設定頁**
- 扣：無分組長捲動（-10）、目標 20px（-5）、無搜尋（-5）→ **80 分，邊緣合格**
- 建議修：分組＋搜尋（-15 變 0）→ 95 分

## 評分輸出格式（寫進回報）

```
互動體驗評分：XX / 100
扣分項：
- 主動作不明確（-10）：登入與註冊按鈕同尺寸
- 對比度不足（-10）：灰色按鈕文字 3.2:1
判定：<80 不合格 → 修正清單 → 重評
```

## 與自檢清單的關係

`anti-patterns-checklist.md` 是「逐項打勾」的詳細版；本檔是「計分判定」的量化版。**兩個都要做**：先打勾自檢，再計分判定。
