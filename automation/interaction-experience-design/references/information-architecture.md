# 資訊架構（Information Architecture，完整版）

> **使用時機**：規劃導覽、頁面組織、功能分組、命名、疊頁與返回時；決策樹「導覽／組織」分支。

來源：Morville, P. & Rosenfeld, L. *Information Architecture: For the Web and Beyond*（IA 領域經典教科書）。

資訊架構 = 內容與功能的**組織、標籤、導覽、搜尋**方式。決定「東西放在哪、叫什麼名字、怎麼找到」。

## 一、組織方案（Organization Schemes）

把功能／內容分類的方式：

| 方案 | 依據 | 適用 |
|---|---|---|
| 任務導向 | 使用者要做的事 | 工具類 App（「發文」「管理」「分析」） |
| 對象導向 | 給誰用的 | 多人系統（「我的」「團隊」「管理員」） |
| 主題導向 | 內容主題 | 內容網站（新聞、產品分類） |
| 時間導向 | 時間順序 | 活動、歷史、版本 |

**規則**：
- 分類要**互斥**（一項只屬一類）且**完整**（每項都有歸屬）
- 使用者能說出「XX 功能在哪一類」——測不出來就重分
- 用使用者語言命名分類（「發文」不是「內容發布模組」）

## 二、心智模型與 Card Sorting（卡片分類法）

**心智模型**：使用者心中「東西應該放在哪」的直覺。

**Card Sorting 實作**：
1. 把功能寫在卡片上（10-30 張）
2. 請真實使用者（5-10 人）自己分組、命名
3. 觀察多數人的分組與命名 → 照著做
4. 開放式（自由分組）測心智模型；封閉式（給定分類）驗證命名

**為什麼重要**：開發者與使用者的心智模型常不一致——「進階設定」開發者放技術分組，使用者找「帳號」底下。

## 三、深度 vs 廣度（Depth vs Breadth）

- **廣度優先**：一層多選項（如 7 個 Tab）勝過多層深挖（3 層×3 選項）
- 深度 **≤3 層**（首頁 → 類別 → 內容）；超過 3 層要理由
- 每多一層 = 多一次點擊 = 多一次迷路機會

**判斷**：同層選項 ≤7（Hick/Miller），超過就該分組或收合。

## 四、導覽系統（Navigation Systems）

| 類型 | 用途 | 實例 |
|---|---|---|
| 全域導覽 | 所有頁面都有的主結構 | 側邊欄、底部 Tab（≤5 個）、頂部選單 |
| 局部導覽 | 某個區塊內的子頁 | 分頁 Tab、列表→詳情 |
| 情境導覽 | 頁內相關連結 | 「相關文章」「你可能也喜歡」 |
| 麵包屑 | 深層頁面的位置指示 | 首頁 > 帳號 > 安全設定 |

**選擇原則**：
- 主功能（每天用）：底部 Tab 或側欄頂部——一鍵可達
- 次要功能（偶爾用）：收進側欄中段或「更多」
- 少用功能（設定類）：側欄底部或獨立「設定」頁
- 下鑽流程：疊頁（新頁蓋舊頁）＋ 固定返回
- 長流程（>3 步）：步驟條（Step 1 of 4）

**側邊欄不是唯一解**：
- 5 個以內主要功能 → Tab 分組
- 功能間有從屬關係 → 主頁＋下鑽疊頁
- 大量但可分組 → 側欄只放組別（可展開）

## 五、疊頁與返回（Stack Navigation）

- 下鑽頁面用**疊頁**：新頁從右推入蓋在舊頁上，使用者知道「後面還有上一頁」
- **返回**：左上角按鈕（固定位置）＋ 右緣滑動（手機）＋ 鍵盤 Esc（桌面）
- 前景／後景視覺區分：當前頁不透明、後方頁可透視（推入時）——滑動一下就能看到後方
- 深層（≥3 層）：標題清楚＋麵包屑；避免無限下鑽
- 返回鍵永遠回到「上一個畫面」，不是「首頁」（例外：從首頁進來的）

## 六、標籤與命名（Labeling）

- 使用者看得懂的詞（「發文」不是「Post 管理」）
- 全站一致（同一功能同一名稱，不換名字）
- 避免術語、內部簡稱、創意命名（「寶藏庫」使用者不知道是檔案）
- 標籤要能預測內容（「設定」就真的是設定，不要塞功能）

## 七、搜尋與瀏覽互補

- 內容多（>100 項）時要搜尋；少時瀏覽即可
- 搜尋結果要有摘要、過濾、排序
- 搜不到時給建議（相近詞、清空條件）

## 實作流程

1. 列出所有功能（使用者任務清單）
2. 卡片分類法測心智模型（或用常識先分再驗證）
3. 定組織方案與命名
4. 選導覽模式（Tab／側欄／疊頁／步驟條）
5. 畫出每頁的導覽地圖（sitemap），確認深度 ≤3、每頁有返回
6. 用任務分析走一遍關鍵流程
