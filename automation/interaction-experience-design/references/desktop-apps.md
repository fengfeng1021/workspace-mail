# 桌面應用（egui／原生視窗）適用指引

本 skill 的學理對任何介面都適用，但桌面應用有幾個與網頁不同的地方。用 egui（Rust）或任何桌面框架時，照這份調整。

## 學理對照（哪些照用、哪些調整）

| 學理 | 桌面應用怎麼套 |
|---|---|
| Nielsen 10 啟發式 | **完全照用**（狀態可見、一致性、錯誤預防…與平台無關） |
| Fitts's Law | 目標大小用**像素**：主動作 ≥40-48px；滑鼠環境次要動作可小些（20px 也可點）但主次層級不變 |
| Hick's Law | **照用**：一屏選項 ≤7，導覽分組 |
| Miller 7±2 | **照用** |
| Gestalt | **照用**：間距分組、相似性 |
| Jakob's Law | 桌面慣例：**確定/取消**（Windows 慣例確定在左、macOS 在右）、**Esc 取消**、**Ctrl+S 儲存**、視窗右上角關閉 |
| Norman | **照用**：Affordance（egui 按鈕要有按鈕樣式，不要裸文字可點）、對應、約束、回饋 |
| 認知負荷 | **照用** |
| WCAG | 桌面對比照用（4.5:1）；鍵盤操作＝**Tab 走訪＋快捷鍵**；目標大小 Windows 建議 ≥24px |
| ISO 9241 | **照用**（有效性/效率/滿意度） |

## egui 特定注意事項

- **視窗佈局**：左側導覽（SidePanel）+ 右側內容（CentralPanel）是 egui 慣例——對應 IA 的全域導覽＋內容區，照 IA 原則做分組與層級
- **主動作**：egui 的 `Button::new(...).fill()` 可以做主按鈕強調色；次要動作用 `weak()` 或文字連結——**主次必須可區分**
- **折疊分組**：`CollapsingHeader` 就是逐步揭露（Progressive Disclosure）——進階設定收進摺疊區
- **狀態可見**：egui 沒有內建 loading 元件——長任務要自己顯示進度（`ProgressBar`、spinner、log 區域）
- **快捷鍵**：常用動作配快捷鍵（egui `ctx.input` 偵測 Ctrl+S 等）＝ Nielsen 7 彈性效率
- **表格與列表**：大量帳號用 `ScrollArea` + 篩選 + 搜尋（別平鋪 50 行無過濾）＝ Hick + 認知負荷
- **工具提示**：`on_hover_text` 就是 Nielsen 10 的幫助
- **中文字體**：egui 預設字體不含中文——載入系統字體（msjh.ttc），否則全是方塊（無障礙＋可讀性）

## 桌面應用評分（audit.py 不適用時的流程）

audit.py 只吃 HTML；桌面應用用**人工評分流程**（references/scoring.md），加桌面特定檢查：

1. 照常：從 100 分起，照 scoring.md 扣分表扣
2. 加扣（桌面特有）：
   - 無快捷鍵（-5）：常用操作要 Ctrl 快捷鍵
   - 視窗不可縮放／佈局不適應（-5）：resizable + 內容自適應
   - Esc 無法取消/關閉彈窗（-5）
   - 長列表無搜尋/過濾（-5）
   - 無工具提示（-5）：圖示按鈕要有 hover 說明
3. 加分：快捷鍵齊全（+5）、狀態列顯示進度（+5）

## 範例：多功能工具 App 的導覽（egui）

- ❌ 側邊欄 15 個功能平鋪、無分組、無摺疊
- ✅ SidePanel 放 3-5 個分組（CollapsingHeader），主功能直接露出、次功能摺疊、設定在最底；視窗左上標題顯示目前頁面；深層操作（批次執行）用獨立視窗或 modal 且可 Esc 關閉

## 與網頁版的差異速記

| 項目 | 網頁 | 桌面（egui） |
|---|---|---|
| 返回 | 左上角＋手勢 | 視窗關閉＋Esc＋麵包屑（多層頁面時） |
| 慣例 | 搜尋右上 | 選單列（File/Edit/View）＋工具列 |
| 目標大小 | ≥24px | ≥24px（滑鼠可略小但主動作仍要大） |
| 回饋 | 頁面內 | 狀態列＋log＋彈窗 |
