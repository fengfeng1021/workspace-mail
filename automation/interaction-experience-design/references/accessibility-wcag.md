# 無障礙（WCAG 2.2 互動相關，完整版）

> **使用時機**：檢查對比度、鍵盤操作、目標大小、動效、表單無障礙時；決策樹「無障礙」分支。

來源：W3C. *Web Content Accessibility Guidelines (WCAG) 2.2*（AA 等級為目標）。

無障礙不是附加功能：對比、鍵盤、焦點這些要求同時也是「讓所有使用者更順手」的設計。

## 一、色彩與對比

| 要求 | 數值 | 檢查 |
|---|---|---|
| 文字對比度 | ≥4.5:1（一般文字）；≥3:1（大字 ≥24px／粗體 ≥18.66px） | 灰底灰字幾乎必失敗 |
| 非文字對比（圖示、邊框、狀態） | ≥3:1 | 圖示、輸入框邊框、狀態色 |
| 不只靠顏色傳達 | 錯誤不能只變紅，要加圖示／文字 | 「紅字」+「！」圖示 |

**實務**：工具列元素（圖示按鈕）對比 ≥3:1；停用狀態不能只剩透明度變化（要加紋理或說明）。

## 二、鍵盤操作

- **所有功能鍵盤可達**：Tab 走訪、Enter/Space 觸發、Esc 關閉
- **焦點可見**：永遠有明顯的 focus 環（不要 outline:none 不移除）
- 焦點順序合理（跟視覺順序一致）
- 自訂元件要有鍵盤協定（下拉：上下選、Enter 確認、Esc 關閉）

## 三、目標大小（WCAG 2.2 新增）

- 操作目標 **≥24×24 CSS px**（2.2 AA）
- 間距夠時可豁免（目標間有 24px 間隔）
- 對照 Fitts：主要動作應該更大（≥44px 是行動端慣例）

## 四、動效與減少動態

- `prefers-reduced-motion: reduce` 時：停用或大幅簡化動效
- 閃爍 ≤3 次／秒（避免癲癇風險）
- 動效不阻擋操作（loading 不能卡住鍵盤）

## 五、表單與輸入

- 每個欄位有**可見標籤**（不是只靠 placeholder——placeholder 會消失且對比常不足）
- 錯誤提示：**欄位旁**（不是只在頁頂）＋ 文字描述（不只顏色）＋ `aria-describedby` 關聯
- 錯誤後焦點移到第一個錯誤欄位
- 輸入格式要求說清楚（「日期：YYYY/MM/DD」）

## 六、語意與輔助技術

- 正確的 HTML 語意（button 用 button，不是 div onclick）
- 圖示按鈕有 `aria-label`（「搜尋」不是只有放大鏡圖）
- 狀態變化通知（`aria-live`：載入完成、購物車更新）
- 標題層級正確（h1 > h2 > h3，不跳級）

## 七、頁面結構

- 頁面標題有意義（「設定 - 我的帳號」）
- 跳過導覽的連結（Skip to content）
- 深層頁有麵包屑（同時是無障礙與可用性）

## 檢查清單（互動相關）

- [ ] 所有文字對比 ≥4.5:1？
- [ ] 圖示與狀態 ≥3:1？
- [ ] 錯誤不只靠顏色？
- [ ] 全鍵盤可操作、focus 可見？
- [ ] 目標 ≥24px（主要動作更大）？
- [ ] reduced-motion 有處理？
- [ ] 每個欄位有可見標籤、錯誤在欄位旁？
- [ ] 圖示有 aria-label？

## 與其他理論的關係

- 對比 4.5:1 ＝ 可見性（Nielsen 1）
- 目標 ≥24px ＝ Fitts's Law 的下限
- 鍵盤與語意 ＝ 通用設計（不犧牲任何使用者）
- 無障礙做好，一般使用者也會更順（路緣效應：為輪椅做的斜坡，推車的人也用）
